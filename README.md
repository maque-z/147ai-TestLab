# 147ai TestLab

一个自用的图像生成 API 测试台。用来回答一个具体问题：**接口的实际行为，和它文档里承诺的行为，是否一致？**

不是生图工具。生图是手段，观察是目的。

---

## 为什么会有这个东西

调用第三方图像 API（尤其是经过网关转发的）时，反复遇到同一类麻烦：

- 请求 `size=2048x2048`，返回的图实际是 1024×1024
- 响应体声称 `output_format: "png"`，实际字节是 JPEG
- 请求 `n=3`，只回来 1 张
- 配置的是 A 模型，网关悄悄换成了 B 模型
- 请求透明背景，拿回来的是**画上去的棋盘格**，不是真的 alpha 通道

这些都不会报错。HTTP 200，响应体结构完整，看起来一切正常 —— 除非你逐项去核对。

所以这个工具做的事，就是把「请求了什么」和「实际拿到什么」摆在一起，让不一致的地方自己显形。

---

## 核心设计：请求 → 实际

每张结果卡片都是一张对照表。左边是发出去的值，右边是**测量出来的**值，不是 API 自己说的值。

```
项      请求              → 实际
尺寸    2048×2048           1024×1024      ← 标红
格式    png                 jpeg           ← 标红
└ API 声称  png             jpeg           ← 响应体与字节不符
张数 n  3                   1              ← 标红
背景    transparent         不透明          ← 标红
```

几条贯穿始终的原则：

**1. 实际值必须独立测量，不能采信 API 的自述**

- 图片格式：读文件头的 magic bytes，不看响应体的 `output_format`
- 图片尺寸：等浏览器解码后读真实像素，不看请求参数
- 是否透明：对解码后的像素采样 alpha 通道

最后一条尤其关键。读文件头只能回答「这个格式声明了 alpha 通道」，而一张全白不透明的 RGBA 图同样会声明 alpha —— 只有真去看像素，才能区分「真透明」和「一张不透明的图装在支持透明的容器里」。

**2. 「未设置」和「任何具体值」是两种不同的情况**

参数留空时，请求里**根本不带这个字段**，而不是填一个猜测的默认值。因为「API 自己会选什么」本身就是要观察的对象之一 —— 替它填上默认值，就等于把答案预先写进了问题。

**3. 越界的值也要能发出去**

后端的参数校验故意比文档宽松。文档说 `n` 最大 10，这里允许到 100；文档说透明背景不能配 jpeg，这里照发不误。

因为「文档说不行」和「实际不行」是两件事，而两者的差距正是这个工具要找的东西。真正拒绝的只有不可能成立的输入 —— 负数、无上限的字符串、超出 0–100 的压缩率。

**4. 拿不准的，如实说「拿不准」**

API 不回传的信息（比如 quality 实际生效与否），卡片上就显示 `—`，不做推断。测不出来的（比如跨域图片无法采样 alpha），报告「无法采样」而不是猜一个。

## 功能

### GPT Image 模块

针对 `gpt-image-2` 系列。

- **生成** — `/v1/images/generations`
- **编辑** — `/v1/images/edits`，最多 16 张参考图，支持蒙版
- **测试** — 一套固定探针，一键跑完并生成可复制的报告

参数矩阵会展开成笛卡尔积，每个组合一个独立请求，并发发出，结果逐个流式回来。10 个比例 × 3 档分辨率的尺寸表可以整行整列批量勾选，也可以自由填写任意 `宽x高`。

**蒙版编辑器**：可以直接在图上涂抹要重绘的区域，也可以导入外部 PNG。上传前会本地校验 —— 必须是 PNG、必须有 alpha 通道、尺寸必须与主图逐像素相等。这三条不满足，上游会返回一个语焉不详的 400，不如在本地就说清楚。

**透明背景验证**：图片背景可在 `棋盘格 / 白 / 黑 / 品红` 之间一键切换（预览中按 `B`）。这不是装饰 —— 静态棋盘格背景下，真 alpha 和模型画上去的棋盘格看起来完全一样，切换背景可以当场证伪：真透明的会跟着变，画上去的纹丝不动。

### Gemini 模块

针对 Gemini 图像模型，覆盖两个不同的接口形态：

- **原生** — `/v1beta/models/{model}:generateContent`
- **OpenAI 兼容** — `/v1/chat/completions`，靠 `modalities` 开启图像输出

`utils/bananaSpec.ts` 把官方文档里的模型能力表转录成了代码 —— 哪个模型支持哪些尺寸、哪些宽高比。UI 据此标注「文档说这个组合应该可用」，卡片再对照实际结果。文档没给的数字就返回 null，界面显示「文档未列出」，不编造一个期望值出来。

### 其它

- 多用户，各自独立的 API 配置（baseurl / key / 模型 / 超时）
- 自助注册（可关闭）+ 管理员账号管理
- 登录限流：IP 维度，超限锁定
- 批次可整体停止，也可以单张停止
- 全屏预览：缩放、拖拽、跨卡片翻页

## 快速开始

### 本地开发

```bash
# 后端
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload        # :8000

# 前端
cd frontend
pnpm install
pnpm dev                             # :5173，/api 已代理到 :8000
```

首次启动前先配置 `.env`：

```bash
cp .env.example .env
```

`SECRET_KEY` 用 `openssl rand -hex 32` 生成。`DEFAULT_PASSWORD` 填一个初始管理员密码 —— 它只在数据库为空时用来创建首个账号，账号存在之后就被忽略，重启不会重置密码。

> 必须用 `pnpm`。仓库锁的是 `pnpm-lock.yaml`，没有 `package-lock.json` —— `npm install` 读不了它，会把所有间接依赖重新浮动解析，装出一棵和锁文件不同的依赖树。

### 本地 Docker

```powershell
.\scripts\local-start.ps1            # http://127.0.0.1:8080
```

> 用 `127.0.0.1` 而不是 `localhost`：Windows 上 `localhost` 优先解析到 IPv6 `::1`，而 Docker 的端口映射只监听 IPv4。

### 服务器部署

见 `docker-compose.yml` 顶部的宝塔配置步骤。首次部署后可以注册快捷命令：

```bash
bash scripts/install-alias.sh
```

之后在任意目录：

```
deploy    更新部署（备份数据库 → 拉代码 → 构建前端 → 修权限 → 重建容器 → 等健康检查）
dlog      实时后端日志
dps       容器状态
```

`deploy.sh` 是幂等的，重复执行安全。数据库存在 Docker volume 里，每次部署前自动打包备份，保留最近 10 份。

## 关于安全

这是自用工具，运行时加固不是重点。有几件事说在前面：

- `GET /image-gen/config` 会原样返回该用户自己存的 `api_key`
- 注册默认开放。这是有意的：每个账号有独立的 API 配置，新用户必须填自己的 key，烧的是自己的额度。要关掉在 `.env` 里设 `ALLOW_REGISTRATION=false`
- 后端容器只绑定 `127.0.0.1`，公网访问一律经 Nginx 反代

如果要部署到公网并给不认识的人用，上面这些都需要重新考量。

## 一点说明

代码里的注释密度偏高，而且大多在解释「为什么」而不是「做了什么」。这是刻意的 —— 这个项目里有相当多的决定，是踩过坑之后反着做的：

- `deps.py` 里每个依赖都自己开短生命周期的会话，因为一次生图要 60–120 秒，用 `Depends(get_db)` 会让数据库连接在整个上游调用期间一直被占着，连接池瞬间见底
- `deploy.sh` 整个脚本体包在 `{ }` 里，因为它自己会 `git pull` 改写自己，而 bash 是边读边执行的
- 蒙版导出时把 alpha 二值化，因为画笔用的是 75% 不透明度，`destination-out` 只能把 alpha 降到 ~64，而上游把任何 alpha > 0 的像素都当作「不要重绘」

这些原因不写下来，下一个人（或者三个月后的自己）很可能会把它们「优化」回去。
